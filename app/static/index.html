Pipeline

1. Model. Gemma 4 12B (4-bit QAT) with a LoRA adapter reads the numbered transcript and writes one JSON object: identity, chief complaint, assessment / response / education bullets (each with the verbatim quote and turn numbers it relies on), typed facts and risk flags.

2. Rules (no model). 16 deterministic validators check the JSON against the transcript: valid schema, quotes really in the cited turns, numbers / drugs / names spoken in the call, planned-vs-completed wording, negatives kept negative, hedges kept, Not-Applicable gate, risk flags. A near-miss quote is repaired automatically.

3. Render. A deterministic renderer turns the JSON into the exact reference text format.

4. Judge (optional, live mode). The base Gemma model, with frozen prompts, checks faithfulness, completeness and calibration. The judge was validated before it was used. We hand-edited 90 summaries with known defects (50 used to tune the prompts, then 40 fresh ones run once with the prompts frozen). Faithfulness: kappa 0.90 on the tuning set and 1.00 on the fresh set (10 of 10 edits caught, 0 of 30 clean summaries flagged; small sample). Completeness: kappa 0.61 on the fresh set; reliable for missing nurse actions and instructions, weak for missing findings. Calibration: kappa 0.55; reliable for planned-vs-completed only. Details: llm_judge/README.md.

5. Routing. A summary with a rule error that survives repair, or invalid JSON, is marked REVIEW or FAILED for a nurse instead of being presented as final. No automatic summary should be trusted without that gate.

Research prototype on synthetic data. Not a medical device; every summary must be reviewed by a clinician.
